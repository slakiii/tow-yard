# Level packs and author ghosts — implementation plan

> **For Hermes:** implement task-by-task; one commit per task; `love tests` green between tasks.

**Goal:** make a batch of levels authorable in one pass and shippable as built-in levels, each carrying the author's own recorded line as a ghost the player races against — with ghosts switchable off.

**Architecture:** a `levels/` folder (one `.tylevel` + optional sibling `.tyrun` per level) becomes the source of truth; `lib/levels.lua` becomes a generated catalogue. The author ghost is loaded lazily, verified with the existing `run.verify` before it is allowed on screen, and raced under a single rule: you race whichever of (your best, the author's) is faster.

**Tech stack:** LÖVE 11.5 / LuaJIT, pure `lib/` modules with injected disk/codec, headless `love tests`, `--smoke` for rendering, Python only to move files out of LÖVE's sandbox.

## §1 — Data schema

### `levels/<id>.tylevel` — unchanged format

The existing `levelfmt.encode` text. No new keys are added: the author time is *derived* from the run (`run.verify`'s `final.time`), so a level file and its ghost cannot disagree.

```
id straight-back
series training
order 1
name Straight back
hint Reverse straight back into the bay. ...
bounds 0 0 60 40
spawn 46 20 0
bay 22 20 9 4 0 6
par 30
apron 2
wall hedge 29 14 46 0.6 0
...
```

### `levels/<id>.tyrun` — unchanged format

`run.encode(run, codec)` output (`TOWYARD RUN 1` header + base64 frames). Already verified by `run.verify` against `level.id`, `levelfmt.content_hash(level)` and `hash.build_hash()`.

### Generated `lib/levels.lua`

Same table shape as today, produced by `levelfmt.to_lua`, plus one export the tests need:

```lua
local levelfmt = require("lib.levelfmt")

local M = {}

local RAW = {
    {
        id = "straight-back",
        series = "training",
        order = 1,
        ...
    },
}

-- generated by `love . --pack build` from levels/*.tylevel -- do not edit
M.ALL = {}
for i, level in ipairs(RAW) do
    M.ALL[i] = levelfmt.resolve(level)
end
M.RAW = RAW

function M.get(i) ... end
function M.find(id) ... end
return M
```

### Runtime attachment (never in a file, never in the hash)

```lua
level.author = { time = 27.83, text = "<TOWYARD RUN 1 ...>", run = <decoded> }
```

### `settings.txt` (save dir)

```
TOWYARD SETTINGS 1
ghosts rival
```

### Schema invariants (tests enforce)

1. Every `levels/*.tylevel` decodes with `levelfmt.decode` and passes `levelcheck`.
2. `lib/levels.lua`'s `RAW` equals what `levels/` builds — same ids, same order, same `content_hash` per level (stale catalogue = red suite).
3. A `.tyrun` without a `.tylevel` of the same id, or one that fails `run.verify`, **fails the build** (never silently dropped).
4. `level.author` is never written into `.tylevel`, never enters `content_hash`, never enters `build_hash`.
5. `settings.txt` unknown keys are preserved on save (a new build must not eat an older build's setting).
6. Ids stay unique across the pack and a series stays contiguous with `order` 1..n (existing `levelcheck` rules).

## §2 — Semantics / pure functions

```lua
-- lib/pack.lua -- assemble the catalogue from the folder
function M.build(files)        -- files = { ["straight-back"] = "<tylevel text>", ... }
    -- returns entries (in series/order/id order), errors (list of strings)

-- lib/author.lua -- the shipped run, on the level, or a reason it is not
function M.attach(level, read, codec)   -- read = function(path) -> text|nil
    -- returns { time, text, run } or nil, why

-- lib/rival.lua -- who you race today
function M.pick(own, author, mode)      -- own/author = ghost tables or nil, mode = "off"|"rival"|"both"
    -- returns { entries = { ... }, names = { ... } } (empty for "off")

-- lib/settings.lua -- one small key/value store over an injected disk
function M.open(disk) -> self
function M.get(self, key, fallback)
function M.set(self, key, value) -> bool   -- dirty flag
function M.save(self) -> ok, err
```

**Contracts**

- `pack.build`: order is `series` (first-seen) → `order` → `id`; a duplicate id, a missing `id`, a failed `levelcheck`, or an unreadable file is an **error**, and any error means no output.
- `author.attach`: a missing file is `nil, "no author run"` (normal, silent); a present file that fails to decode or verify is `nil, "<reason>"` and the shell prints it under `--smoke`/the debug key, exactly like `ghost_note`.
- `rival.pick`: `rival` → the faster of the two (tie goes to the player's own); `both` → author first, own second; `off` → empty. A nil entry is never returned.
- `settings.get`: missing file or unknown key returns the fallback; `set` never rewrites bytes that did not change (the smoke asserts the disk stays quiet).

## §3 — Contracts (cross-cutting)

- **Identity is the content hash.** `id`/`series`/`order` stay out of it, so re-sorting a campaign or renaming a level never invalidates a run. The author run is pinned the same way as a player's.
- **Simulation pinning.** `hash.build_hash()` covers the physics constants only, so an author run survives ordinary releases and is refused the moment tuning changes. When that happens the pack build fails and names the file; re-record the line, do not "fix" the ghost.
- **Verify before draw.** No code path renders an author run that `run.verify` refused. `author.attach` is the only loader.
- **Generated file ownership.** `lib/levels.lua` is generated; the header says so. Hand edits are caught by the stale test, not silently overwritten (`tools/install-pack.py` refuses when the working copy differs from the last generated file unless `--force`).
- **Sandbox stays.** The editor still writes only to the save dir. Installing a pack is a Python copy step, exactly like `tools/apply-level.py`.
- **No fabricated ghosts.** An author time only exists if a run parked and verified.

## §4 — Layout / UI contract

**Level select row** (`lib/draw.lua`, campaign rows)
- default: `name · best · pips · par` as today.
- level has an author run: a small ghost glyph after the name, and the author time in the time column on a second, dimmer line (`author 0:27.83`).
- author beaten (best ≤ author time): the ghost glyph is filled and the author time is drawn in the amber ghost colour.
- no author run: nothing at all changes.

**Result card** (`D.overlay`)
- existing: counted time, delta vs record, record line, `NEW BEST` / `FIRST PARK` / `INVALID`.
- with an author run: one extra line under the record — `author 0:27.83   +3.41` — and a state `AUTHOR BEATEN` beside `NEW BEST` when this attempt beats it (never on a damaged attempt).

**Ghost rendering** (`D.ghost`, `main.lua` draw)
- author ghost: silhouette, amber, label `AUTHOR` above the rig.
- own ghost: silhouette when alone; **trail** when both are on screen (so two bodies never merge).
- `H` cycles `off / rival / both`; the toast names the state (`ghosts: rival  -  author 0:27.83`). The setting persists in `settings.txt`.

**Editor** (`D.editor_ui`, `main.lua`)
- a `PACK` tab beside the campaign/custom list: the folder's levels, with `duplicate`, editable `series`/`order`, and a `KEEP LINE` marker when a verified author run is attached.
- saving a pack level writes `drafts/<id>.tylevel` + `drafts/<id>.tyrun` (sandbox); the rail says `draft ready - run tools/install-pack.py`.

**Step 1: Write failing test**

```lua
local pack = require("lib.pack")
local levelfmt = require("lib.levelfmt")

function M.builds_entries_in_series_then_order_then_id_order()
    local a = levelfmt.encode({ id = "b-two", series = "s1", order = 2, name = "B",
        spawn = { x = 4, y = 4, th = 0 }, bay = { x = 10, y = 10, w = 6, h = 4, tol = 0.1 },
        bounds = { x0 = 0, y0 = 0, x1 = 20, y1 = 20 }, par = 30, walls = {}, cones = {}, surfaces = {} })
    local b = levelfmt.encode({ id = "a-one", series = "s1", order = 1, ... })
    local entries, errors = pack.build({ ["b-two"] = a, ["a-one"] = b })
    H.expect(#errors == 0, "a well-formed pack has no errors")
    H.expect(entries[1].id == "a-one" and entries[2].id == "b-two", "order, not filename order")
end

function M.refuses_a_duplicate_id_and_a_broken_file()
    local entries, errors = pack.build({ ["x"] = "not a level", ["y"] = levelfmt.encode({ id = "dup", ... }) })
    H.expect(entries == nil, "one bad file means no catalogue")
    H.expect(#errors >= 1 and errors[1]:find("x"), "the error names the file")
end
```

**Step 2:** `love tests` → RED (`module 'lib.pack' not found`).

**Step 3: Implement**

```lua
local levelfmt = require("lib.levelfmt")
local levelcheck = require("lib.levelcheck")
local M = {}

local function order_key(e) return e.series or "", e.order or math.huge, e.id or "" end

function M.build(files)
    local entries, errors = {}, {}
    for name, text in pairs(files) do
        local lvl, err = levelfmt.decode(text)
        if not lvl then
            errors[#errors + 1] = name .. ": " .. tostring(err)
        else
            local ok, why = levelcheck.check(lvl)
            if not ok then errors[#errors + 1] = name .. ": " .. tostring(why)
            else entries[#entries + 1] = lvl end
        end
    end
    if #errors > 0 then return nil, errors end
    table.sort(entries, function(a, b)
        local as, ao, ai = order_key(a)
        local bs, bo, bi = order_key(b)
        if as ~= bs then return as < bs end
        if ao ~= bo then return ao < bo end
        return ai < bi
    end)
    -- duplicate ids are a pack error: two levels cannot share a ghost's identity
    for i = 2, #entries do
        if entries[i].id == entries[i - 1].id then
            return nil, { entries[i].id .. ": listed twice" }
        end
    end
    return entries, errors
end
return M
```

## §8 — Risks / trade-offs

**A tuning change invalidates every shipped ghost.** `build_hash()` covers the physics constants, which is the correct semantics — a run recorded under other physics is not a fair ghost — but it means a retune forces re-recording the pack. Mitigation: the build fails loudly and names the files, so a release cannot ship ghosts that silently never appear.

**Two ghosts is more clutter than one.** Mitigated by the rule "author = silhouette, own = trail when both", which is why the trail rendering exists at all; if a playtest says it still reads as one body, the fallback is `both` drawing only the faster ghost with a label, never two silhouettes.

**A generated `lib/levels.lua` can drift from the folder.** Mitigated by the stale test (Task 2) and the installer's `--force` guard (Task 4). The rule "never hand-edit it" has to live in the file header, not only in the docs.

**Authoring still needs the two-hop install.** This is deliberate: LÖVE cannot write outside the save dir, and a game that can rewrite its own level data can corrupt it. The cost is one command per batch, not per level.

**Sibling `.tyrun` files are binary-ish text.** `run.encode` output is base64, so a diff shows a changed blob rather than a readable one — acceptable because a ghost's content is not reviewable anyway; the *level* diff stays readable.

## §9 — Explicitly out of scope

- An in-game browser or downloader for other people's packs (no server exists).
- Online leaderboards; the author time is shipped data, not a network result.
- Per-level ghost settings (the setting is global).
- Re-recording ghosts automatically; a stale ghost is dropped, never "repaired".
- Compressing or changing the run format.
- Unlock gating of any kind (decided: everything open).
- A GUI installer; the flow is commands plus the in-game PACK tab.
